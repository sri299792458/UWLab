## Frames and units

Joint order is shoulder pan, shoulder lift, elbow, wrist 1, wrist 2, wrist 3. Joint values
are **radians**, distances are **meters**, and JSON/YAML quaternions are **w,x,y,z** unless
a field explicitly names another ordering. SciPy normally expects x,y,z,w.

`lab_scene.yml` collision-box poses and the calibrated exported URDF use the robot's
`base_link` coordinates. The atlas grid and requested cube/grasp positions use the lab
world frame. The atlas config contains the base-to-world transform; use it explicitly.
In the Isaac task, the robot base is at `[0.177660, 0.377695, 1.466000]` with quaternion
`[0.5, 0.5, 0.5, 0.5]`. The tabletop world Z is `0.84235`.
This corrects the physical mounting difference identified on Thunder. The map
has been recomputed at 20 mm spacing; use the matching corrected release.
The URDF's 180-degree conversion from `base_link` to controller `Base` remains
unchanged. See [../MOUNTING_CORRECTION.md](../MOUNTING_CORRECTION.md).
Do not apply this mounting transform a second time to `lab_scene.yml` before a base-frame
cuRobo query. The rendered lab CAD is in millimeters and the Isaac scene scales it by
0.001; the exported cuRobo boxes and robot meshes are already in meters.

The atlas tool frame is `umi_grasp_center`; its transform is recorded in `tool_offset`.
It differs from the UR flange/default zero TCP `tool0` used for the collector controller
and payload center of gravity. Read the supplied transform rather than treating these
two tool points as interchangeable.

## Collision model and its scope

The map assumes an **empty, fully open hand**, with all six modeled finger coordinates
zero. It includes Thunder's arm, fingers, D405 camera and mount, and the lab's 33 oriented
collision boxes. A carried object, closed hand, cables, people and new obstacles require
appropriate robot-side scene updates. The map does not observe the live lab.

The accepted map uses 239 fitted spheres, 1 mm added sphere radius, 2 mm combined
self-pair padding, **50 mm clearance from the eight columns `lab_7` through `lab_14`**,
and 1 mm clearance from other lab geometry. The YAML's self-collision ignore pairs
and the config's fixed-base/world exclusion are part of this model. Merely loading
the raw YAML into a default planner does not apply all of those rules.
`umi_sphere_geometry.py` shows the implemented margins and coordinate transforms.

The sphere approximation missed one 4.96 mm finger/upper-arm hull overlap in the saved
2,048-configuration comparison. The original 17 convex hulls and an FCL checker are
included for independent path checks. `SourceCollisionChecker` defaults to a uniform
1 mm clearance; **it does not automatically enforce the separate 50 mm column margin**.
`thunder_sim2real/check_motion_hulls.py` shows how the collection validation applies
the column requirement separately. Check transitions and interpolation along the path,
not just the destination. The atlas itself is an endpoint lookup, not a path certificate.

## Collector and dynamics identification

The workstation folder is independently installable without Isaac. The controller is the
pinned UW Cartesian controller with Thunder's calibration and supplied link inertials.
The selected full-amplitude excitation lasts 8 seconds and runs at 500 Hz. The outward-pose
server validation covers the requested waveform and simulated responses at that pose;
it does not establish physical tracking or collision clearance from the current posture.

Copy the candidate JSON, then fill actual robot IP, PolyScope version, physical tool mass
and flange-frame center of gravity. Keep the physical tool configuration consistent with
the model. `simulation_payload_reference.json` reports the modeled open-empty tool:
1.00260655 kg, CoG `[-0.00027272, 0.00714345, 0.06427591]` m in `tool0`.
It excludes several unmodeled adapter/cable/fastener contributions listed in that file.
Collector payload fields deliberately remain unset until physical values are supplied.

The collector's default invocation only prints a plan. `--execute` is required to command
the robot after its initial joint and stationary checks. The robot-side agent should use
the parent README for the collection contract, gains, cleanup and data validation.
The later hardware evidence includes the recorded workstation configuration and
the incomplete outward diagnostic recording. A completed fitting dataset and fitted
Thunder profile are still required. Stage-2 training requires an actual validated
real-record fit; smoke-test synthetic profiles are rejected by production loading.

Follow UWLab's published system-identification procedure: return one completed raw
`thunder-fit.pt`, the actual collection JSON, collector log and validator output. Include
the Git commit and any local code changes. The same recording is used for fitting and
